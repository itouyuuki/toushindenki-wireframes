### ① 保存時に検索用DBへ登録できるか → **できる**

ブロックエディタで「保存」を押すと、**通信が2回**走ることを確認した（見立てどおり）。

| 順 | 通信 | 型番の状態 | `wp_after_insert_post` で検索用DBに入った値 |
|---|---|---|---|
| 1 | 本文の保存（REST API） | **まだ古い／新規なら空** | 古い型番（新規なら空） |
| 2 | メタボックスの保存（約0.5〜1.6秒後） | 保存処理で新しい型番が入る | **新しい型番**（正しい値で上書き） |

- **2回目の通信でも `save_post` → `wp_after_insert_post` が走る。** しかも型番の保存（`save_post`）の**後**に `wp_after_insert_post` が来る。
  → **`wp_after_insert_post` で同期するだけで、最終的に正しい型番が入る。** (a)〜(c) の追加対策は不要
- ずれるのは2回目が終わるまでの**1〜2秒だけ**。その間に検索されると古い型番で出るが、実害はほぼない
- **型番だけ変えて保存**も正しく反映された。ただし型番欄だけの変更ではエディタが「未保存の変更あり」と判定しない
  （`isEditedPostDirty()` が false）。保存ボタンは押せるが、**保存せずに画面を離れても警告が出ない**。
  → 先方の手順書に「型番を変えたら必ず保存」と書く／気になるなら型番欄を (b) のブロックエディタ用の欄で作る
- 2回目の通信が失敗した場合（回線断・JSエラー）は古い型番のまま残る → 全件再構築ボタンで回収する前提は変わらない

### ② 公開状態の同期 → **`wp_after_insert_post` 1本で全部拾える**

| 操作 | WordPress | 検索用DB | 備考 |
|---|---|---|---|
| 下書き保存・公開 | draft / publish | 同じ | |
| 非公開・レビュー待ち | private / pending | 同じ | 検索では `publish` だけ出す |
| ゴミ箱へ | trash | trash | |
| **ゴミ箱から復元** | **draft** | draft | ⚠ **公開には戻らない**（WordPress 5.6 以降の標準動作）。下記 |
| 予約投稿が公開時刻に公開（cron） | publish | publish | 自動で追随した |
| 削除（ゴミ箱を経由） | trash | trash | |
| 完全削除 | （なし） | **行を削除** | `before_delete_post` で削除 |
| クイック編集（タイトル変更） | publish | タイトルも更新 | **型番は消えない**（下記） |

- **どの操作でも `wp_after_insert_post` が走った。** `transition_post_status` を別に使う必要はない。
  完全削除だけ `before_delete_post` を足す。→ `実装メモ_検索設計.md` の「使うフック」はこの2本に減らせる
- **クイック編集では型番欄が送られてこない。** 保存処理で「型番欄が送られてきたときだけ保存する」
  （nonce の確認で判定）にしておけば、型番は消えない。**ここを雑に書くと全件の型番が空で上書きされる**ので実装時の必須事項
- ⚠ **ゴミ箱から戻すと「下書き」になる。** 先方が「間違えて捨てた製品を戻したのに検索に出ない」と言う原因になる。
  → 手順書に「復元したら公開し直す」と書く（`wp_untrash_post_status` フィルタで元の状態に戻す手もある）

### ⚠ 新しく見つかったズレ：カテゴリー側の変更では同期が走らない

| 操作 | 結果 |
|---|---|
| **カテゴリー名を変更**（例：IPカメラシステム → 別名） | 検索用DBの `cat_name` は**古い名前のまま** |

> 必須事項は「型番欄が送られてきたときだけ保存」「検索に出すのは publish のみ」「カテゴリー変更時の再同期」。

### まず試すこと：CF7 標準の `default:get`（10/30 追記・未検証の見立て）

CF7 にはフォームタグのオプションで **URL の GET パラメータを初期値にする機能が標準で付いている。**
うまくいけば独自のフィルタを書かずに済む。

```
[text your-model default:get]    ← ?your-model=TS-0182 の値が入る
[text your-product default:get]  ← ?your-product=… の値が入る
```

※ パラメータ名とフォームタグの名前を揃える必要がある。
※ 8/17 の「JS での初期値注入は不可」とは別ルート（サーバー側でフォームを出す時点で値が入る）。

- [ ] `default:get` で型番・品名の両方が入るか
- [ ] **日本語の品名**（URL エンコードされた値）が文字化けしないか
- [ ] ページキャッシュを入れた状態で、**別の製品の値が出てこない**か
- [ ] 入った値を客が書き換えられても問題ないか（初期値なので書き換え可が自然。読み取り専用にするかは要判断）
- [ ] `default:get` で足りない場合に限り、サーバー側フィルタで実装する → **不要だった**
