## 3-0.【失効】製品は「投稿」ではなく「カスタム投稿タイプ」にする

**2026-08-18、社長判断で「標準の投稿タイプを使う」と決定。この項目は失効。**

<details><summary>失効した検討内容（記録）</summary>


**8/17 会議 26:23〜27:00 の「1手の絞り込み」の話は、これのこと。**

標準の「投稿」＋「カテゴリー」で製品を管理すると、**商品ごとに増えたカテゴリーが、
お知らせなど他のカテゴリーと同じ一覧に並ぶ。** 製品が数百件あればカテゴリーもその数だけ増え、
投稿一覧・カテゴリー一覧の視認性が壊れる。だから絞り込みを1手挟む必要が出る、という指摘だった。

**カスタム投稿タイプ＋専用のカスタムタクソノミーにすれば、製品とお知らせは別の箱に分離できる。**
これが「開発の仕方が変わってくる」の中身。

- [ ] カスタム投稿タイプ＋専用タクソノミーで、お知らせと完全に分離できることを確認
- [ ] 分離した状態で、製品 500〜1000 件でも管理画面の一覧性が実用に耐えるか
- [ ] 企画書の開発工程の見積もりは **投稿機能 ～400,000／カスタム投稿 ～600,000（＋税）**。
      **カスタム投稿側になる根拠**として、この一覧性の問題を整理しておく
